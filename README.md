# AL-thmany Extractor 2.14.0 — Unified Group Memory

هذه النسخة تنقل فلسفة **WA-Workspace: الاستخراج | الفحص | النشر** إلى تطبيق Android يعمل مع تطبيق WhatsApp الحقيقي (`com.whatsapp`) أو WhatsApp Business (`com.whatsapp.w4b`) **بدون WhatsApp Web وبدون WebView**.

> ملاحظة تقنية: Android لا يتيح للتطبيق الوصول إلى WhatsApp Web Store أو `chat.sendMessage()` أو قاعدة بيانات واتساب الخاصة. لذلك 2.13 يحافظ على نفس التسلسل والضمانات قدر الإمكان عبر واجهة Android الحقيقية: Accessibility/Event-first للاستخراج والفحص والنشر النصي، وAndroid `ACTION_SEND` للمرفقات. لا توجد طبقة Shizuku حقيقية في هذا الإصدار بعد.

## ما الجديد في 2.14.0

> **2.14.0:** المزامنة تبني Group Database موحدة مشتركة بين الاستخراج والنشر، وفتح القروب أصبح يعتمد على الذاكرة/القائمة والتمرير قبل Search. أضيفت أيضًا أوضاع فحص فقط / انضمام فقط / فحص + انضمام مع حفظ النتيجة قبل الانتقال. لا يتم حفظ AccessibilityNodeInfo.


- **مزامنة أغنى للقائمة:** اسم المحادثة + غير المقروء + آخر نشاط ظاهر + مؤشرات النشاط/القابلية للنشر/Community Parent، مع بقاء المرشحين غير مؤكدين حتى فتحهم والتحقق منهم كقروب.
- **تحديد سريع للقروبات:** الكل، إلغاء الكل، غير المقروءة، النشطة، القابلة للنشر، وغير المؤكدة؛ مع بحث واختيار يدوي.
- **Deep Extraction:** التقاط الروابط أثناء التمرير للأقدم، زر تحميل الرسائل الأقدم إن كشفته واجهة واتساب، Strict End Proof، Checkpoint واستكمال ثم القروب التالي تلقائيًا.
- **التقاط روابط متعدد الأسطح:** `text` + `contentDescription` + `hintText` + `tooltipText` + `URLSpan` + public Accessibility extras، ثم normalization/dedupe.
- **Scan Exact-Once:** رابط واحد في كل لحظة، فتح مرئي، Connectivity Guard يعيد **نفس الرابط** بعد عودة الشبكة، Stable Result Gate، وحد Adaptive للحالات غير الواضحة 5.6s، ثم Commit قبل الانتقال. الفحص لا يضغط Join/Request.
- **Publish Native:** Preflight + القروبات المحددة والقابلة للنشر فقط + Single-Flight + Run Token + حماية `UNCERTAIN` لمنع إعادة الإرسال العمياء بعد نتيجة غير محسومة.
- **أنواع النشر:** نص واحد، رسائل متعددة بتوزيع دائري، جهات اتصال كنص (`الاسم | الرقم`)، VCF، VCF + نص، وصورة + تعليق عبر مسار المشاركة الأصلي في Android.
- **سرعة صادقة:** Turbo في النشر = 1.0 ثانية فعلية كحد pacing بين القروبات، وليست تسمية واجهة غير مطابقة للمحرك.
- **إصلاح Build معروف:** إزالة import `androidx.compose.foundation.layout.weight` الذي كان يوقف Kotlin 2.3.21 في GitHub Actions.

راجع `NATIVE_PARITY_2.13_AR.md` و`CHANGELOG_2.13_AR.md` للتفاصيل.

# AL-thmany Extractor TurboCore Android v2.10.0

تطبيق Android مخصص لاستخراج روابط HTTP/HTTPS من مجموعات WhatsApp وWhatsApp Business **مباشرة من التطبيق المثبت على الهاتف** عبر `AccessibilityService`، بدون WhatsApp Web وبدون WebView.



## v2.10.0 — TurboCore

هذا الإصدار يركز على **السرعة الفعلية مع الدقة والثبات** بدون تحويل التطبيق إلى Joiner وبدون تعطيل إثبات النهاية أو حماية منع تكرار النشر.

أهم التطويرات:

- **Active-engine event routing:** خدمة Accessibility ترسل أحداث واتساب للمحرك الذي يملك الواجهة فقط؛ لا يتم إيقاظ الاستخراج والفحص والنشر معًا لكل حدث.
- **One-slot event backpressure:** كل محرك يحتفظ بأحدث حدث فقط ويطرح الأحداث القديمة المتراكمة، لمنع backlog عند السحب السريع أو تغيرات واجهة واتساب الكثيفة.
- **Turbo Event-first timings:** تقليل مهلات settle في Hyper/Turbo/Smart مع إبقاء Strict End Proof كما هو.
- **No redundant relaunch:** إذا كانت نسخة واتساب الصحيحة أمام المستخدم بالفعل فلا يعاد تشغيلها بلا داعٍ قبل الاستخراج/النشر.
- **Atomic sync ownership:** مزامنة أسماء القروبات أصبحت تدخل نفس بوابة RuntimeOperationCoordinator حتى لا تتداخل مع Scan أو Publish.
- **Batch Scan Import:** استيراد آلاف روابط الدعوات من النص أو نتائج الاستخراج يتم في Transaction واحدة بدل كتابة SQLite لكل رابط.
- **SQLite WAL tuning:** `synchronous=NORMAL` + `temp_store=MEMORY` + `busy_timeout` + WAL checkpoint أصغر لتقليل ضغط التخزين أثناء الدفعات.
- **Faster Scan Pro:** انتظار حدثي أقصر مع بقاء التحقق المستقر وعدم تحويل الشاشة الفارغة/Loading إلى نتيجة نهائية مبكرة.
- **Faster Publish UI detection:** تقليل settle بعد أحداث الواجهة مع الإبقاء على pacing غير صفري بين القروبات وحماية عدم إعادة الإرسال بعد قبول ضغطة Send.
- **Profile/package guards محفوظة:** لا يتم التعامل مع نسخة واتساب مختلفة عن الهدف المحدد.

> السرعة هنا ناتجة من تقليل الانتظار الصناعي والتراكمات الداخلية، لا من تجاوز قيود WhatsApp أو تعطيل التحقق.

## ما تم تطويره في v2.1

### محرك الاستخراج العميق — الافتراضي

1. يبحث عن اسم القروب في WhatsApp ويفتحه.
2. يثبت هوية القروب من عنوان المحادثة في أعلى النافذة، لا من أي تطابق نصي عشوائي.
3. يقرأ كل نص مكشوف في شجرة Accessibility ويستخرج روابط HTTP/HTTPS فورًا.
4. يسحب نحو الرسائل الأقدم عبر `ACTION_SCROLL_BACKWARD`، مع Gesture fallback عند الحاجة.
5. يلتقط الروابط **أثناء تغيّر واجهة واتساب** وليس بعد انتهاء السحب فقط.
6. إذا ظهر عنصر تحميل الرسائل الأقدم، يضغطه ثم يراقب دفعة الرسائل الجديدة ويستخرج منها قبل متابعة السحب.
7. لا ينتقل للقروب التالي إلا بعد إثبات نهاية مستقلة ومتكررة، أو ظهور حالة نظام بنيوية مؤكدة.
8. عند عدم ثبوت النهاية يعيد نفس القروب حتى 3 محاولات افتراضيًا بدل نقله لنهاية القائمة.

### السرعة

- **HyperDrive:** الأسرع؛ مهلات شديدة القصر للأجهزة السريعة والواجهات المستجيبة.
- **Turbo دقيق:** الافتراضي؛ سريع جدًا مع التقاط حدثي وحماية النهاية.
- **ذكي مستمر:** توازن سريع مع وقت إضافي للرسم عند القروبات الثقيلة.
- **متوازن:** هامش أوسع للاستقرار.
- **دقيق وآمن:** أبطأ مستوى لاختبار القروبات الضخمة أو الأجهزة البطيئة.

لا توجد مهلة ثابتة طويلة بين القروبات. بعد شهادة نهاية صحيحة يبدأ القروب التالي مباشرة. ويمكن ضبط أقصى دورات تحميل الأقدم من الواجهة إلى 1000 / 2000 / 4000 / 10000 (الافتراضي 2000 مثل الأداة الأصلية).

### أوضاع الاستخراج

- **عميق:** قراءة المحادثة والسحب حتى أقدم سجل متاح. هذا هو الافتراضي.
- **ذكي تلقائي:** يجرب العميق أولًا، وإذا تعذر بسبب بنية إصدار واتساب يحاول تبويب الروابط.
- **استخراج سريع:** يفتح معلومات القروب > الوسائط والروابط والمستندات > الروابط ثم يمر على القائمة.
- **جميع الدردشات:** محرك السحب المتداخل عالي الإنتاجية لكل القروبات المحددة، قريب من وضع all-chats في الأداة الأصلية ضمن حدود Android.
- **الجديد فقط:** يتوقف عند Anchor سابق أو فاصل غير المقروء، مع Bootstrap محدود عند أول تشغيل.

### إثبات النهاية

النهاية العادية لا تعتمد على فشل سحب واحد. المحرك يجمع أدلة مثل:

- ثبات توقيع المحتوى لعدة جولات.
- تكرار عدم ظهور محتوى أقدم بعد السحب.
- عدم وجود زر تحميل الرسائل الأقدم.
- عدم ظهور روابط أو نصوص جديدة أثناء فترة التحقق.
- بقاء هوية القروب المفتوح صحيحة أثناء فحص النهاية.
- فحص هدوء مستقل مرتين قبل الانتقال.

### حالات نهاية بنيوية

يدعم المحرك حالات نظام عربية/إنجليزية مثل:

- حد سجل الرسائل المتاح على هذا الهاتف.
- بطاقة نظام تفيد أن المستخدم انضم للقروب أو عبر رابط دعوة.
- شاشة مجتمع رئيسية تعرض «استكشاف المجتمع» بدل محادثة.
- محادثة فارغة وغير قابلة للسحب بعد ثلاث محاولات متتالية.

تم وضع بوابة بنيوية إضافية حتى لا تُفسَّر عبارة كتبها عضو داخل رسالة عادية على أنها حالة نظام: العنصر وأجداده/أبناؤه التفاعليون يُفحصون قبل قبول الحالة.

## المزامنة

- يمر على قائمة محادثات WhatsApp حتى 4000 اسم.
- يفحص قسم المحادثات المؤرشفة أيضًا عندما يكون متاحًا.
- Android لا يكشف قاعدة بيانات القروبات الخاصة بواتساب، لذلك أسماء المزامنة التلقائية تُحفظ كـ **غير مؤكدة**.
- قبل استخراج اسم مكتشف تلقائيًا، يفتح التطبيق معلومات المحادثة ويتحقق من مؤشرات خاصة بالقروبات مثل «مغادرة المجموعة / إضافة أعضاء / دعوة عبر رابط»؛ المحادثات الخاصة تُتخطى.
- يمكن إدخال أسماء القروبات يدويًا أيضًا، اسمًا في كل سطر.

## الحفظ والاستكمال

- SQLite محلي للروابط والقروبات والحالة.
- Checkpoint لكل قروب: Anchor + توقيع المحتوى + رقم جولة السحب + وضع الاستخراج.
- حفظ مرحلي كل عدة جولات.
- Pause / Resume / Stop.
- إشعار دائم للتقدم مع أزرار إيقاف مؤقت / استكمال / إنهاء.
- عند استكمال قروب غير مكتمل، يستخدم المحرك سرعة Turbo للوصول إلى Anchor السابق ثم يعود للسرعة المختارة.

## منع التكرار

القاعدة الأساسية هي `(normalized_url, group_name)`.

لا يرفع التطبيق عداد مرات الظهور لمجرد أن نفس فقاعة الرسالة ظهرت مرة أخرى بعد سحب متداخل، لأن Accessibility لا يضمن Message ID ثابتًا في كل إصدارات WhatsApp. هذا قرار مقصود لمنع أرقام وهمية. يحتفظ التطبيق برابط فريد لكل قروب، وبعدد الروابط الفريدة عالميًا بشكل منفصل.

## النتائج والتصدير

- بحث بالرابط أو اسم القروب.
- نسخ جميع الروابط.
- XLSX.

- TXT.
- JSON.

## دعم WhatsApp

- `com.whatsapp`
- `com.whatsapp.w4b` (WhatsApp Business)

المحرك يعزل جميع افتراضات واجهة واتساب تقريبًا في:

`app/src/main/java/com/althmany/extractor/engine/WhatsAppUiAdapter.kt`

إذا غيّر WhatsApp نصًا أو بنية واجهة، يتم تعديل Adapter بدل إعادة بناء التطبيق كله.

## شرط التشغيل المهم

Android يعزل بيانات التطبيقات. لذلك AL-thmany لا يقرأ قاعدة بيانات WhatsApp ولا ملفات الرسائل الخاصة به. الاستخراج يتم من العناصر التي يكشفها WhatsApp داخل `AccessibilityNodeInfo` أثناء وجود WhatsApp في الواجهة.

لذلك:

- يجب أن تكون الشاشة مفتوحة وغير مقفلة أثناء الأتمتة.
- إذا أخفى إصدار واتساب معيّن نص الرسائل عن Accessibility فلن يستطيع التطبيق اختراع تلك البيانات؛ يجب عندها تحديث Adapter أو الاستراتيجية.
- من الضروري إجراء تجربة أولية على عدد قليل من القروبات قبل تشغيل آلاف القروبات.

تمت ترقية واجهة ومحرك «الفحص» إلى Scan Pro: سرعات فحص مستقلة، نطاقات تشغيل، إعادة تحقق ذكية للحالات المؤقتة فقط، درجات ثقة، اكتشاف اسم الدعوة وعدد الأعضاء عندما يظهران في واجهة واتساب، تمييز المجموعة/المجتمع، حالة مستقلة لطلب الانضمام المرسل، تسجيل الإشارة التي أدت للتصنيف، ومدة كل فحص. وضع «إعادة فحص الكل» أصبح أمرًا لمرة واحدة ثم يعود تلقائيًا إلى الاستكمال العادي حتى لا يعيد الطابور من البداية بعد الانقطاع.

## v2.4 — Publish

أضيفت خاصية **النشر** كتَبويب ثالث بجانب الاستخراج والفحص. النشر يعمل فقط على القروبات التي يحددها المستخدم، مع معاينة قبل البدء، تحقق من هوية القروب، Pause/Resume، سجل SQLite، وإجراء حماية من التكرار بعد تنفيذ ضغطة الإرسال. راجع `PUBLISH_FEATURE_AR.md` و`CHANGELOG_2.4_AR.md`.
